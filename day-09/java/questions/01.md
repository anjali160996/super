# Q01 — Log scan: find the hot method

A service scans server logs for `ERROR` lines. It is correct but takes **~600 ms** on 800k lines. Reading the code top-to-bottom will not tell you which line costs the most — **profile it**.

## Starter code

```java
import java.util.ArrayList;
import java.util.List;

public class ErrorScan {
    static List<String> build(int n) {
        List<String> lines = new ArrayList<>(n);
        for (int i = 0; i < n; i++) {
            lines.add(i % 50 == 0 ? "ERROR disk full id=" + i : "INFO ok id=" + i);
        }
        return lines;
    }

    static int countErrors(List<String> lines) {
        int n = 0;
        for (String line : lines) {
            if (line.matches(".*\\bERROR\\b.*")) {
                n++;
            }
        }
        return n;
    }

    public static void main(String[] args) {
        List<String> lines = build(800_000);
        long t = System.nanoTime();
        int errors = countErrors(lines);
        System.out.println("errors=" + errors + " ms=" + (System.nanoTime() - t) / 1_000_000);
    }
}
```

## Your task

1. Run `main` and note wall time.
2. Attach **VisualVM** (Sampler → CPU) while `countErrors` runs.
3. Find the method that dominates CPU time.
4. Fix **only** the bottleneck — keep the same result (`errors=16000`).

## What VisualVM should show

- Hot stack under `countErrors`
- Time in regex / pattern matching — not in `build` or `ArrayList` growth

## Fix hint (after you profile)

Compile the pattern **once**, reuse a `Matcher` per line (or use `String.contains("ERROR")` if you accept the simpler rule).

## Expected behavior

```text
errors=16000
// after fix: ms drops to roughly 50–150 (machine-dependent)
```
