# Q02 — Price service: threads blocked on one lock

Eight worker threads price SKUs in parallel. Wall time is **~400–500 ms** for 1,600 tasks — far slower than single-threaded math would suggest. Use VisualVM **Threads** + **Sampler** to see why.

## Starter code

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.*;

interface Pricer {
    long price(int sku);
}

class CpuPricer implements Pricer {
    public long price(int sku) {
        long x = sku;
        for (int i = 0; i < 200_000; i++) {
            x = x * 1103515245L + 12345 + i;
        }
        return x & 0xFFFF;
    }
}

class AuditedPricer implements Pricer {
    private final Pricer inner;
    private long calls;

    AuditedPricer(Pricer inner) {
        this.inner = inner;
    }

    public synchronized long price(int sku) {
        calls++;
        return inner.price(sku);
    }
}

public class PriceService {
    public static void main(String[] args) throws Exception {
        Pricer pricer = new AuditedPricer(new CpuPricer());
        int tasks = 1_600;
        ExecutorService pool = Executors.newFixedThreadPool(8);
        long t = System.nanoTime();
        try {
            List<Future<Long>> futures = new ArrayList<>();
            for (int i = 0; i < tasks; i++) {
                int sku = i;
                futures.add(pool.submit(() -> pricer.price(sku)));
            }
            long sum = 0;
            for (Future<Long> f : futures) {
                sum += f.get();
            }
            System.out.println("sum=" + sum + " ms=" + (System.nanoTime() - t) / 1_000_000);
        } finally {
            pool.shutdown();
        }
    }
}
```

## Your task

1. Run `main` — note wall time.
2. In VisualVM: **Threads** tab → many threads **blocked** waiting on `AuditedPricer`.
3. Sampler → see time inside `synchronized price` while `CpuPricer.price` runs **inside** the lock.
4. Fix so audit counting stays correct but **heavy work is outside** the lock.

## What VisualVM should show

- Threads in `BLOCKED` or parked on `AuditedPricer`
- Only one thread doing real work at a time despite pool size 8

## Fix hint (after you profile)

Hold the lock only to increment `calls`; call `inner.price(sku)` **before** or **after** the synchronized block.

## Expected behavior

```text
sum=<same as before>
// after fix: ms drops to roughly 120–200 with 8 threads
```
