## Domain model

Implement JPA entities with the properties below. Use appropriate relationships (`@ManyToOne`, etc.) and validate required fields on create/update.

### Make (manufacturer)

| Field         | Type    | Notes                          |
|---------------|---------|--------------------------------|
| `id`          | Long    | Auto-generated primary key     |
| `name`        | String  | Required, unique               |
| `country`     | String  | Required, e.g. `"Japan"`       |
| `foundedYear` | Integer | Optional                       |

### Model

| Field        | Type     | Notes                                      |
|--------------|----------|--------------------------------------------|
| `id`         | Long     | Auto-generated primary key                 |
| `make`       | Make     | Required FK                                |
| `name`       | String   | Required, e.g. `"Camry"`                   |
| `bodyType`   | enum     | Required — see **BodyType** below          |
| `launchYear` | Integer  | Optional                                   |

**BodyType:** `SEDAN`, `SUV`, `HATCHBACK`, `COUPE`, `CONVERTIBLE`, `PICKUP`, `WAGON`

Unique constraint: `(make_id, name)` — one model name per make.

### Engine

| Field            | Type    | Notes                              |
|------------------|---------|------------------------------------|
| `id`             | Long    | Auto-generated primary key         |
| `name`           | String  | Required, e.g. `"2.0L Turbo I4"`   |
| `displacementCc` | Integer | Required, displacement in cc       |
| `cylinders`      | Integer | Required                           |
| `horsepower`     | Integer | Required                           |
| `torqueNm`       | Integer | Required, torque in N·m            |
| `fuelType`       | enum    | Required — see **FuelType** below  |

**FuelType:** `PETROL`, `DIESEL`, `ELECTRIC`, `HYBRID`, `CNG`

### Gear (transmission)

| Field           | Type    | Notes                              |
|-----------------|---------|------------------------------------|
| `id`            | Long    | Auto-generated primary key         |
| `type`          | enum    | Required — see **GearType** below  |
| `numberOfGears` | Integer | Required, e.g. `6` for 6-speed     |

**GearType:** `MANUAL`, `AUTOMATIC`, `CVT`, `DCT`

### Car (listing)

| Field         | Type       | Notes                                    |
|---------------|------------|------------------------------------------|
| `id`          | Long       | Auto-generated primary key               |
| `make`        | Make       | Required FK                              |
| `model`       | Model      | Required FK; must belong to the make     |
| `engine`      | Engine     | Required FK                              |
| `gear`        | Gear       | Required FK                              |
| `variantName` | String     | Required trim/variant, e.g. `"XLE Sport"` |
| `modelYear`   | Integer    | Required, e.g. `2024`                    |
| `price`       | BigDecimal | Required, listing price                  |
| `mileageKm`   | Integer    | Required; `0` for brand-new              |
| `color`       | String     | Required                                 |
| `vin`         | String     | Optional, unique when present            |
| `description` | String     | Optional                                 |
| `available`   | boolean    | Required, default `true`                 |

On create/update, reject requests where `model.make` does not match `car.make`.

## REST API (Phase 1)

Base path: `/api`

Implement standard CRUD for each resource. Return `201 Created` with body on POST; `404` when id not found; `400` for validation errors with a readable message.

| Resource | Path           |
|----------|----------------|
| Make     | `/api/makes`   |
| Model    | `/api/models`  |
| Engine   | `/api/engines` |
| Gear     | `/api/gears`   |
| Car      | `/api/cars`    |

### Additional read endpoints

| Method | Path                         | Behavior                               |
|--------|------------------------------|----------------------------------------|
| GET    | `/api/makes/{makeId}/models` | All models for a make                  |
| GET    | `/api/cars`                  | List cars; optional query params below |

**Car list filters (all optional, combinable):**

- `makeId` — filter by make
- `modelId` — filter by model
- `minPrice` / `maxPrice` — inclusive price range
- `available` — `true` or `false`

Use DTOs for request/response bodies where appropriate; do not expose JPA entities directly if it causes circular JSON.

## Database & configuration

- PostgreSQL as the sole datastore.
- `application.yml` — app port `8080`, datasource URL/host/db name; username/password via environment variables (`DB_USERNAME`, `DB_PASSWORD`) with sensible local defaults.
- Schema: `spring.jpa.hibernate.ddl-auto=update` for Phase 1 (migrations can come later).

## Docker

1. **Dockerfile** — multi-stage build: compile with Gradle/JDK 17, run on JRE 17. Expose port `8080`.
2. **docker-compose.yml** (recommended for local dev) — PostgreSQL service + app service; app waits for DB.
3. Build the image locally (Docker must be running on your machine):

```bash
docker build -t automobile-api:day04 .
```

Optional run with compose:

```bash
docker compose up --build
```

## Expected behavior (smoke test)

After `docker compose up --build`:

```bash
# Create make
curl -s -X POST http://localhost:8080/api/makes \
  -H 'Content-Type: application/json' \
  -d '{"name":"Toyota","country":"Japan","foundedYear":1937}'

# Create model (use make id from response)
curl -s -X POST http://localhost:8080/api/models \
  -H 'Content-Type: application/json' \
  -d '{"makeId":1,"name":"Camry","bodyType":"SEDAN","launchYear":1982}'

# List cars (empty initially)
curl -s 'http://localhost:8080/api/cars?makeId=1'
```
