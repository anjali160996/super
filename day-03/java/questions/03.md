# Q03 — Collectors on your Day 1 order batch

**Continuation from Day 1 Q03** — reuse the same `Order` type from async order processing.

You already process `List<Order>` concurrently. Before or after processing, the business team wants rollups by region.

## What changes from Day 1

Extend `Order` with two fields (keep existing `id` and payload):

- `String region` — e.g. `"IN"`, `"US"`
- `double amount`

Your Day 1 executor / summary code can stay; this question adds **read-only aggregation** with Collectors.

## Requirements

1. Implement on a list of orders (same shape as Day 1 Q03):
   - `Map<String, Double> totalByRegion(List<Order> orders)` — `groupingBy` + `summingDouble`
   - `Map<String, Long> countByRegion(List<Order> orders)` — `groupingBy` + `counting`
   - `Map<Boolean, List<Order>> partitionHighValue(List<Order> orders, double threshold)` — `partitioningBy` where `true` means `amount >= threshold`
2. Use Collectors — no manual `HashMap` loops for these three methods.
3. Demo in `main` with the same batch style as Day 1 (ids + payloads + new fields).

## Constraints

- Reuse / extend your Day 1 `Order` class; do not create a parallel order model.
- Empty input → empty map (not `null`).

## Expected behavior

```text
orders = [
  Order(1, "payload-a", "IN", 100),
  Order(2, "payload-b", "IN", 50),
  Order(3, "payload-c", "US", 200),
  Order(4, "payload-d", "US", 30)
]

totalByRegion(orders)      → {IN=150.0, US=230.0}
countByRegion(orders)      → {IN=2, US=2}

partitionHighValue(orders, 100)
// true  → orders with amount >= 100
// false → orders with amount < 100
```
