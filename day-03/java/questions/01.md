# Q01 — Stream pipeline on your Day 1 catalog

**Continuation from Day 1 Q01** — reuse `Repository<T>`, `Identifiable`, `User`, and `Product`.

You already store entities in a generic repository. Now query the catalog with the Stream API instead of hand-written loops.

## What changes from Day 1

Add one field to `Product` only:

- `double price`

`User` stays as-is (`id`, `name`).

## Requirements

1. Ensure `Repository<T>` exposes `List<T> findAll()` (add it if your Day 1 version only had `save` / `findById`).
2. Implement `ProductStats summarizeProducts(Repository<Product> catalog, String namePrefix)` returning:
   - `long count` — products whose `name` starts with `namePrefix` (case-insensitive)
   - `double totalPrice` — sum of `price` for those products
   - `OptionalDouble maxPrice` — highest price in that set (empty if none match)
3. Use a **stream pipeline** over `catalog.findAll()` — no manual `for` loop for the core logic.
4. Demo in `main`: save a few `Product`s into `Repository<Product>`, print stats for prefix `"Key"`.

## Constraints

- Reuse your Day 1 types; do not introduce a separate product store.
- Do not mutate the repository or the returned list from `findAll()`.
- Empty match → `count=0`, `totalPrice=0.0`, `maxPrice=OptionalDouble.empty`.

## Expected behavior

```text
Repository<Product> catalog = new Repository<>();
catalog.save(new Product(1L, "Keyboard", 79.99));
catalog.save(new Product(2L, "Keycap Set", 24.50));
catalog.save(new Product(3L, "Mouse", 49.00));

summarizeProducts(catalog, "key")
// count=2, totalPrice=104.49, maxPrice=OptionalDouble.of(79.99)

summarizeProducts(catalog, "Monitor")
// count=0, totalPrice=0.0, maxPrice=OptionalDouble.empty
```
