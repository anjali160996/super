# Q04 — Sort your Day 2 Person list with Comparator

**Continuation from Day 2 Q01** — reuse `Person` and `Address` (including shallow / deep clone if you already implemented them).

You modeled people with nested addresses. Now sort a guest list for a mail merge: by city, then by name.

## What changes from Day 2

Nothing on the model — only add a sort helper that consumes existing `Person` / `Address` types.

## Requirements

1. Implement `List<Person> sortForMailMerge(List<Person> people)` returning a **new sorted list** (input order unchanged) by:
   1. `address.city` ascending (case-insensitive; null city last)
   2. `name` ascending (case-insensitive)
2. Build the comparator with `Comparator.comparing` / `thenComparing` and **method references** (e.g. `Person::getName`, `Address::getCity` via `Person::getAddress` chain).
3. Demo in `main` with at least three people across two cities, including one with the same city to test name tie-break.

## Constraints

- Reuse Day 2 `Person` / `Address`; do not introduce `Employee` or other stand-ins.
- Java 8 `Comparator` static methods only.

## Expected behavior

```text
Input:
  Ada   / Pune
  Zed   / Mumbai
  bob   / Pune
  Amy   / Mumbai

Output order:
  Amy   / Mumbai
  Zed   / Mumbai
  Ada   / Pune
  bob   / Pune    // case-insensitive name within Pune
```
