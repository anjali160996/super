# Q05 — Functional rules layered on your Day 1 validator

**Continuation from Day 1 Q02** — reuse `@NotNull`, `Validator.validate(Object)`, and `UserRegistration` (`name`, `email`).

Reflection-based `@NotNull` checks caught missing fields. Add **composable string rules** with Java 8 functional types for format checks the annotation cannot express.

## What changes from Day 1

Keep `@NotNull` and `Validator.validate()` as they are. Add:

1. `@FunctionalInterface ValidationRule<T>` with `boolean test(T value)` and a **default** method:
   - `default ValidationRule<T> and(ValidationRule<T> other)`
2. Static string rules: `notBlank()`, `minLength(int n)`, `matches(String regex)` — each with a human-readable failure message.
3. `List<String> validateRegistration(UserRegistration reg)` that returns **all** failures:
   - First run existing `@NotNull` validation (reuse `Validator.validate(reg)`)
   - Then, for non-null fields only, apply composed rules on `name` (min length 2) and `email` (must match `".+@.+\\..+"`)

## Requirements

1. Compose rules with `ValidationRule.and` (or `Predicate.and`) — not one giant nested `if`.
2. Collect every failed message in one list (annotation errors + rule errors).
3. Bonus (same file): lazy `Supplier`-backed memo — `T getOrCreate(Supplier<T> factory)` so `factory.get()` runs **at most once** (reuse for an expensive regex / config if you like).

## Constraints

- Do not remove or rewrite Day 1 `@NotNull` behavior; extend it.
- `validateRegistration` must report multiple failures when several rules break (not fail-fast).

## Expected behavior

```text
UserRegistration bad = new UserRegistration(null, null);
validateRegistration(bad)
// includes "name must not be null", "email must not be null"

UserRegistration weak = new UserRegistration("A", "not-an-email");
validateRegistration(weak)
// includes min-length and email-format messages (no @NotNull errors)

UserRegistration ok = new UserRegistration("Ada", "ada@example.com");
validateRegistration(ok)  → []
```
