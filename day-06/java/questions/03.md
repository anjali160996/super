# Q03 — CompletableFuture: chained order notifications

**Continuation from Day 1 Q03** — reuse your `Order` type and async batch-processing idea.

`CompletableFuture` composes async steps without blocking the caller on each individual task. Chain small stages instead of nesting callbacks.

## What changes from Day 1

Keep `Order` as-is (including `region` / `amount` from Day 3 if you added them). This question adds **notification pipelines**, not a new order model.

## Requirements

1. Simulate work with `CompletableFuture.supplyAsync` on the **common pool** (or a small fixed pool you shut down in `main`).
2. Implement `CompletableFuture<String> notifyCustomer(Order order)`:
   - Stage 1: `supplyAsync` → validate order id is positive (else complete exceptionally with `IllegalArgumentException`)
   - Stage 2: `thenApply` → format message `"Order {id} confirmed for region {region}"` (use `"UNKNOWN"` if region is null)
   - Stage 3: `thenApply` → append `" | total={amount}"` when `amount > 0`, else `" | total=N/A"`
3. Implement `CompletableFuture<List<String>> notifyAll(List<Order> orders)` — one future per order, **`allOf`** then collect messages in input order.
4. Demo in `main` with 3 orders; block once at the end with `.join()` or `.get()` and print all messages.

## Constraints

- Use `CompletableFuture` composition (`thenApply`, `allOf`) — not raw `Future.get()` in a loop for each stage.
- Do not swallow exceptions; failed order should fail its future (others still complete).
- No `Thread.sleep` required unless you want to simulate latency.

## Expected behavior

```text
orders = [
  Order(1, "payload", "IN", 100),
  Order(2, "payload", "US", 0),
  Order(3, "payload", null, 50)
]

notifyAll(orders).join()
// [
//   "Order 1 confirmed for region IN | total=100",
//   "Order 2 confirmed for region US | total=N/A",
//   "Order 3 confirmed for region UNKNOWN | total=50"
// ]
```
