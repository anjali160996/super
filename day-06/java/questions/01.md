# Q01 — Enums with fields and behavior

Enums are more than named constants — they can carry state and define methods. Use them when a fixed set of variants each has its own rules.

## Requirements

1. Define `enum DiscountTier` with variants `NONE`, `SILVER`, `GOLD`, `PLATINUM`. Each variant stores:
   - `double rate` — multiplier applied to price (e.g. `0.90` means 10% off)
   - `int minSpend` — minimum cart total required to qualify
2. Add instance methods:
   - `boolean qualifies(double cartTotal)` — `cartTotal >= minSpend`
   - `double apply(double cartTotal)` — if qualified, return `cartTotal * rate`; otherwise return `cartTotal` unchanged
3. Add a static lookup:
   - `Optional<DiscountTier> fromCode(String code)` — match enum name case-insensitively (`"gold"` → `GOLD`); empty if unknown
4. Demo in `main` with three cart totals and two tier codes.

## Constraints

- Use a real `enum`, not a class with `public static final` int constants.
- Constructor and fields on the enum are fine; keep variants immutable after construction.
- `fromCode` must not throw on unknown input — return `Optional.empty()`.

## Expected behavior

```text
DiscountTier.GOLD.apply(5000)     → 4500.0   // 10% off when qualified
DiscountTier.GOLD.apply(500)      → 500.0    // below minSpend, no discount
DiscountTier.fromCode("gold")     → Optional[GOLD]
DiscountTier.fromCode("vip")      → Optional.empty
```
