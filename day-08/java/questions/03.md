# Q03 — Virtual threads at scale: what Q01 cannot do

**Continuation from Day 8 Q01–Q02** — reuse `ProbeTarget`, `ProbeResult`, and `probe(...)`.

Q01 capped concurrency at 32 platform threads. Q02 sped up 500 probes. Here, run **100_000** probes — one virtual thread each. A platform pool cannot do this; virtual threads can.

## Requirements

1. Keep `probe(ProbeTarget)` from Q01.
2. Implement `int runAtScale(int count)`:
   - build `count` targets with `delayMs = 10`
   - start **`count` virtual threads** via `Thread.ofVirtual().name("probe-", 0).start(...)`
   - `CountDownLatch` to await all; return success count (`AtomicInteger`)
3. Demo in `main` with `count = 100_000`. Print wall time and success count.

## Constraints

- Virtual threads only — no fixed platform pool.
- Do not batch into groups of 32; one virtual thread per probe.

## Expected behavior

```text
runAtScale(100_000) → 100_000
// finishes in seconds, not minutes of queueing or OOM from 100k platform threads
```
