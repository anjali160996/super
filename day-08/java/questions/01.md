# Q01 — Endpoint probes with a platform thread pool

Build an uptime probe **without virtual threads**. This is the baseline for Day 8 Q02 and Q03.

Each probe simulates blocking I/O (`Thread.sleep`). A small **fixed platform pool** limits how many probes run at once — the usual pre–virtual-thread approach.

## Requirements

1. Define `record ProbeTarget(int id, int delayMs)` and `record ProbeResult(int id, boolean ok, long elapsedMs)`.
2. Implement `ProbeResult probe(ProbeTarget target)` — sleep `delayMs`, return `ok = true` and elapsed time.
3. Implement `List<ProbeResult> checkAll(List<ProbeTarget> targets)` using **`Executors.newFixedThreadPool(32)`** (try-with-resources):
   - one task per target
   - results in **input order**
4. Demo in `main` with **500** targets (`delayMs` between 50–100). Print wall time and success count.

## Constraints

- Java 21+ is fine, but **do not** use virtual threads or `newVirtualThreadPerTaskExecutor` here.
- Pool size stays **32** — do not raise it to “fix” slowness in this question.

## Expected behavior

```text
checkAll(500 targets, pool=32) → 500 results, all ok
// wall time ~1–2 s (queued batches), not ~25 s sequential
```
