# Q03 — Structured concurrency: first successful quote

**Structured concurrency** (Java 21, `StructuredTaskScope`) treats a group of related tasks as one unit of work: if one branch finishes, siblings can be cancelled; if the scope closes, child tasks are torn down together.

## Scenario

A pricing service asks two upstream providers for a quote. Return the **first successful** result; cancel the slower call.

## Requirements

1. Define `record Quote(String provider, double price)`.
2. Provide two simulated fetch methods (no real HTTP required):
   - `Quote fetchSlow()` — sleep ~800 ms, return `new Quote("slow", 99.0)`
   - `Quote fetchFast()` — sleep ~200 ms, return `new Quote("fast", 101.0)`
3. Implement `Quote firstSuccessfulQuote()` using **`StructuredTaskScope.ShutdownOnSuccess<Quote>`**:
   - `fork` both fetches
   - `join()` on the scope
   - return `scope.result()` (the first subtask that completed successfully)
4. Demo in `main` twice: normal run (expect **fast** provider), and a run where `fetchFast` throws `IOException` so **slow** wins.
5. Document in a one-line comment why the losing task was interrupted after the winner returned.

## Constraints

- Java 21+ (`StructuredTaskScope` is standard in 21, not preview).
- Use try-with-resources on the scope: `try (var scope = new StructuredTaskScope.ShutdownOnSuccess<Quote>())`.
- Do not use `CompletableFuture.anyOf` for this exercise — use structured concurrency API.
- Simulated delays via `Thread.sleep` are fine.

## Expected behavior

```text
firstSuccessfulQuote()           → Quote[provider=fast, price=101.0]

// when fetchFast throws:
firstSuccessfulQuote()           → Quote[provider=slow, price=99.0]
// fast task cancelled after slow succeeds
```

## Hint

`ShutdownOnSuccess` is for "pick first success"; see `StructuredTaskScope.ShutdownOnFailure` when **all** must succeed.
